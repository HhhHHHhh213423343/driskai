# D.Risk AI 数据源与证据策略

## 目标

分析结果必须能回答四个问题：数据来自哪里、何时取得、是否为一手来源、是否经过交叉验证。没有取得证据时显示“待接入”或“已检索无结果”，不以 `0` 代替未知状态。

## 来源优先级

1. 官方一手来源：公司公告与官网、巨潮资讯、证券交易所、国家金融监督管理总局、中国人民银行、中国证监会、国家企业信用信息公示系统、国家统计局、国家发展和改革委员会。
2. 权威媒体和持牌数据：仅作为事件发现或交叉验证，不覆盖官方原文。
3. 聚合数据：AkShare 等用于快速形成结构化指标，关键结论须与公司公告或监管披露交叉核验。
4. 企业内部数据：订单、履约、投诉、工单、系统可用率等只能在获得授权后接入。

## 银行业优先来源矩阵

| 数据领域 | 一手来源 | 用途 |
| --- | --- | --- |
| 监管处罚与风险 | 国家金融监督管理总局及地方派出机构 | 行政处罚、监管措施、许可证、整改要求 |
| 货币政策与执法 | 中国人民银行及分支机构 | 反洗钱、征信、支付结算处罚，利率和货币统计 |
| 银行业监管指标 | 国家金融监督管理总局 | 不良贷款率、拨备覆盖率、资本充足率、流动性等行业基准 |
| 财报与重大事项 | 企业官网/投资者关系、巨潮资讯、上交所、深交所、港交所披露易 | 年报、季报、业绩、问询、诉讼与重大事项 |
| 债券与同业市场 | 中国货币网、中国债券信息网 | 同业存单、金融债、二级资本债、永续债 |
| 企业信用与司法 | 国家企业信用信息公示系统、信用中国、裁判文书网、执行信息公开网、破产重整案件信息网 | 行政处罚、经营异常、诉讼、执行、破产 |
| 消费者与声誉 | 全国 12315、监管通报、企业官方回应 | 投诉、消费者保护、服务质量与声誉事件 |
| 宏观基准 | 国家统计局、人民银行 | GDP、CPI、PPI、PMI、社融、信贷与利率 |

国家企业信用信息公示系统、司法网站、12315 等存在验证码、登录或访问频率限制。系统不绕过限制，而是生成“授权接口/人工原文核验”任务；未完成核验前不得将其解释为“没有风险事件”。

## 多行业覆盖

所有行业共用公司官网、法定披露、证券监管、企业信用、司法执行和权威检索来源，并按行业追加：

- 汽车：工业和信息化部汽车公告、市场监管总局缺陷产品召回、生态环境部。
- 制造：工业和信息化部行业运行、海关总署、生态环境部、应急管理部。
- 医药：国家药监局、药审中心、国家医保局。
- 房地产：住房和城乡建设部、自然资源部。
- 互联网与软件：工业和信息化部、国家互联网信息办公室。
- 能源：国家能源局、生态环境部。
- 未识别行业：仍启用通用法定披露和风险来源，后续可在 `source_registry.py` 中继续增加行业插件。

## 当前连接器

- 公司官网：抓取官网首页及投资者关系、公告、新闻栏目；仅允许同域链接。
- 权威站点检索：通过 `SERPER_API_KEY` 搜索白名单官方域名和少量权威媒体域名。
- 监管与披露入口：按企业行业自动生成来源计划；银行企业额外启用金融监管总局、人民银行、中国货币网和中国债券信息网。
- PDF 证据：提取公告正文，并保存来源 URL、发布时间、采集时间、权威等级和内容哈希。
- 人工核验队列：对需要授权、验证码或原文确认的来源生成任务，并在分析页展示待办。

## 准确性控制

- 仅对白名单域名和企业官方域名进行入库。
- 遵守 `robots.txt`，HTTP 请求最多重试三次。
- 页面必须同时命中企业名称或别名及分析维度关键词，才可成为证据。
- 企业名称、别名、股票代码和统一社会信用代码共同用于实体匹配；入库材料保存实体匹配分数。
- 同一材料可进入多个 Agent，但按“企业 + URL + 分析维度”去重。
- 内容哈希未变化时不重复更新；变化时保留最新采集时间。
- 每条证据保存来源权威分、A–D 证据等级、原文 URL、发布时间、采集时间和内容哈希。
- 权威媒体或持牌检索只承担“发现线索”，最终结论优先引用监管、交易所或企业原文。
- 覆盖率由完整度 40%、时效性 20%、权威可追溯性 25%、交叉验证 15% 组成。

## 运行方式

单企业每日增量：

```text
POST /api/v1/authoritative-ingestion/companies/{company_id}/run?mode=daily&lookback_days=2&max_documents=60
```

首次五年回补：

```bash
cd backend
python run_authoritative_collection.py --mode backfill --backfill-years 5 --max-companies 100
```

每日任务：

```bash
cd backend
python run_authoritative_collection.py --mode daily --lookback-days 2 --max-companies 100
```

也可由调度器调用：

```text
POST /api/v1/authoritative-ingestion/daily/run?mode=daily&lookback_days=2
X-Collection-Key: <COLLECTION_API_KEY>
```

建议每天凌晨执行；两天回看窗口用于覆盖延迟发布和前一日失败重试。五年回补会按自然年切分检索窗口，避免普通搜索只返回近期高排名材料。`COLLECTION_API_KEY` 配置后可保护批量任务和人工核验状态更新接口。`SERPER_API_KEY` 是可选的持牌检索接口；未配置时只影响权威搜索发现能力和历史回补深度，官方直连和人工核验队列仍可工作，界面会明确显示“未接入”。

辅助接口：

- `GET /api/v1/authoritative-ingestion/companies/{company_id}/source-plan`：查看该企业的行业识别、指标和来源计划。
- `GET /api/v1/authoritative-ingestion/runs`：查看批量采集运行记录。
- `GET /api/v1/authoritative-ingestion/review-queue?company_id=...`：查看人工核验队列。
- `PATCH /api/v1/authoritative-ingestion/review-queue/{item_id}`：标记 `verified`、`rejected` 或 `deferred`。

## 状态语义

- `success`：连接器运行成功，并取得可核验材料。
- `no_hit`：连接器成功运行，在当前时间窗未命中。
- `not_connected`：缺少授权/API 或来源只能人工核验，不代表无风险。
- `failed`：本次抓取失败，应在下次每日任务重试。
- `partial`：部分页面或字段可用，不能据此计算完整结论。

前端非宏观 Agent 右上角刷新按钮会运行权威来源采集并重新分析；待授权或需原文确认的来源会进入“人工核验队列”卡片。
